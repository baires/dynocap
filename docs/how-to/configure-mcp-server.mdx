# Configure the MCP Server

The **Model Context Protocol (MCP)** enables AI coding assistants like Claude Desktop, Cursor, and Cline to call local tools.

MicroVM includes a first-party MCP server package (`@microvm/mcp`) that exposes tools for starting tasks, executing commands in an isolated Linux microVM, inspecting diffs, and exporting patches.

---

## Prerequisites

1. MicroVM CLI built and signed (`./scripts/build-macos.sh`).
2. Node 22 runtime prepared (`microvm runtime prepare . --runtime node:22`).
3. Build the TypeScript packages:
   ```sh
   npm run typecheck
   npm run --prefix sdk/mcp build
   ```

---

## MCP Server Security Policies

By default, `@microvm/mcp` enforces strict security boundaries:

- **Offline Only by Default:** The LLM cannot allocate network interfaces or connect to external hosts.
- **Opt-in Network Modes:** You must explicitly enable network flags via environment variables when launching the server:
  - `MICROVM_MCP_ALLOW_FILTERED=1`: Permits HTTPS access to `registry.npmjs.org` and Git origins.
  - `MICROVM_MCP_ALLOW_NAT=1`: Permits unrestricted outbound NAT connectivity.

## Connecting to Claude Desktop

Add MicroVM to your Claude Desktop configuration file:

📁 `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "microvm": {
      "command": "node",
      "args": ["/Users/YOUR_USER/playground/microvm/sdk/mcp/dist/bin.js"],
      "env": {
        "MICROVM_MCP_ALLOW_FILTERED": "1"
      }
    }
  }
}
```

Restart Claude Desktop. You will see the MicroVM tools appear in the hammer icon list.

---

## Connecting to Cursor

To configure Cursor to use MicroVM:

1. Open **Cursor Settings** -> **Features** -> **MCP Servers**.
2. Click **+ Add New MCP Server**.
3. Set:
   - **Name:** `microvm`
   - **Type:** `command`
   - **Command:** `node /Users/YOUR_USER/playground/microvm/sdk/mcp/dist/bin.js`

## Available MCP Tools

Once connected, your AI assistant can use the following tools:

| MCP Tool              | Purpose                                                                 |
| :-------------------- | :---------------------------------------------------------------------- |
| `microvm_task_start`  | Imports a project tree or Git URL into an isolated task sandbox.        |
| `microvm_task_exec`   | Runs a shell command inside the task's `/workspace`. Streams output.    |
| `microvm_diff`        | Previews unified Git diffs of modifications made by the agent.          |
| `microvm_task_finish` | Shuts down the sandbox and saves the verified patch and execution logs. |
| `microvm_ls`          | Lists active sandboxes and retained task records.                       |
| `microvm_rm`          | Destroys sandboxes or purges retained task directories.                 |
| `microvm_run`         | Boots a raw Linux sandbox without a project tree.                       |
| `microvm_exec`        | Executes a command inside a raw sandbox.                                |
| `microvm_destroy`     | Destroys a raw sandbox.                                                 |

## Typical Prompt Example

You can prompt your assistant like this:

> _"Clone `./my-web-app` into a MicroVM sandbox named `feature-auth`. Run `npm test` inside the sandbox to make sure it's green. Then implement OAuth token validation in `src/auth.js`, verify the tests pass, show me the diff preview, and finish the task."_

The assistant will autonomously invoke `microvm_task_start`, `microvm_task_exec`, `microvm_diff`, and `microvm_task_finish` safely within the Linux microVM.
