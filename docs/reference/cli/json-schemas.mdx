# CLI JSON Schemas

When passed `--json`, management commands print a single line-delimited JSON payload to `stdout`. Absent values are explicitly represented as `null`, timestamps are integer Unix epoch seconds (UTC), and consumers must tolerate extra fields.

---

## 1. Listing Schema (`microvm ls --json`)

Returns an array of sandbox and task records:

```json
[
  {
    "id": "task-8f92b7c1",
    "name": "demo",
    "kind": "task",
    "phase": "running",
    "runtime": "node:24",
    "network": "none",
    "sandboxExpiresAtUnix": 1794958200,
    "resultExpiresAtUnix": 1795563000,
    "resultDirectory": null
  }
]
```

### Fields

| Field                  | Type              | Description                                                                                      |
| :--------------------- | :---------------- | :----------------------------------------------------------------------------------------------- |
| `id`                   | `string`          | Immutable task ID or raw sandbox name.                                                           |
| `name`                 | `string \| null`  | Friendly name assigned at creation, or `null`.                                                   |
| `kind`                 | `string`          | `"task"` (project sandbox) or `"sandbox"` (raw).                                                 |
| `phase`                | `string`          | Lifecycle phase: `"booting"`, `"running"`, `"stopping"`, `"stopped"`, `"completed"`, `"failed"`. |
| `runtime`              | `string`          | Runtime identifier (e.g. `"node:24"`, `"minimal"`).                                              |
| `network`              | `string \| null`  | `"none"`, `"filtered"`, `"nat"`, or `null`.                                                      |
| `sandboxExpiresAtUnix` | `integer \| null` | Absolute TTL deadline in seconds. `null` if VM is stopped.                                       |
| `resultExpiresAtUnix`  | `integer \| null` | Absolute retention deadline for logs and diffs (7 days from creation).                           |
| `resultDirectory`      | `string \| null`  | Absolute path to exported host result directory, or `null`.                                      |

## 2. Creation Schema (`microvm clone --json`)

Returned by `microvm clone` and `microvm task start`:

```json
{
  "id": "task-8f92b7c1",
  "name": "demo",
  "phase": "running",
  "runtimeDigest": "sha256:d8b2...",
  "createdAtUnix": 1794956400,
  "expiresAtUnix": 1794958200,
  "sourceUrl": null,
  "sourceRevision": "4b92c41"
}
```

---

## 3. Finish Schema (`microvm finish --json`)

Returned when a task is finalized and exported:

```json
{
  "id": "task-8f92b7c1",
  "name": "demo",
  "phase": "completed",
  "patchPath": "/Users/user/.microvm/tasks/task-8f92b7c1/result/changes.patch",
  "resultDirectory": "/Users/user/.microvm/tasks/task-8f92b7c1/result",
  "expiresAtUnix": 1795563000
}
```

---

## 4. Inspection Schema (`microvm inspect --json`)

Returned by `microvm inspect NAME`:

```json
{
  "id": "task-8f92b7c1",
  "name": "demo",
  "kind": "task",
  "taskPhase": "completed",
  "sandboxPhase": "stopped",
  "runtime": "node:24",
  "network": "none",
  "createdAtUnix": 1794956400,
  "sandboxExpiresAtUnix": 1794958200,
  "resultExpiresAtUnix": 1795563000,
  "resultDirectory": "/Users/user/.microvm/tasks/task-8f92b7c1/result",
  "patchPath": "/Users/user/.microvm/tasks/task-8f92b7c1/result/changes.patch",
  "sourcePath": "/tmp/demo-project",
  "sourceRevision": "4b92c41"
}
```

---

## 5. Removal Schema (`microvm rm --json`)

Returned by `microvm rm` and `microvm destroy`:

```json
{
  "target": "demo",
  "removed": true,
  "purged": false
}
```

## 6. Doctor Schema (`microvm doctor --json`)

Diagnostic report of host readiness. Findings go to stdout in both modes; the command exits 1 when a required check fails.

```json
{
  "ok": false,
  "home": "/Users/user/.microvm",
  "arch": "aarch64",
  "runtimes": [{ "name": "node", "version": "24" }],
  "checks": [
    {
      "id": "platform",
      "status": "ok",
      "message": "macOS 13+; guest architecture aarch64",
      "recovery": null,
      "fix": null
    },
    {
      "id": "runtime",
      "status": "error",
      "message": "Runtime node:24 is not prepared for aarch64 yet.",
      "recovery": "Run microvm doctor --fix to prepare node:24 (downloads verified inputs; takes a few minutes).",
      "fix": "prepare-runtime"
    }
  ]
}
```

- `status` is `ok`, `warning`, or `error`. Only `error` makes `ok` false.
- `runtimes` is the runtime that was checked: `--runtime`, or the one the project's files call for. It is empty when there was no project. The `runtime` check then lists the prepared runtimes and is a `warning` if there are none.
- `fix` is the repair `doctor --fix` performs for this check on this machine (`restart-daemon`, `build-images`, or `prepare-runtime`), or `null` when the check passes or needs a manual step. When it is set, `recovery` names the exact command.

With `--fix`, the report describes the state after repairs and adds `repairs`, in the order they ran:

```json
"repairs": [
  {
    "fix": "build-images",
    "status": "fixed",
    "summary": "Building the guest image for aarch64",
    "recovery": null,
    "logPath": "/Users/user/.microvm/image-build-....log",
    "note": null,
    "seconds": 20.4
  }
]
```

`status` is `fixed`, `failed`, or `skipped`. A runtime repair is skipped when the daemon restart failed. `note` reports side effects, such as where mismatched image files were moved.
